# Arabic Localization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Arabic as a full second language for the entire site (nav, buttons, labels, theory/quiz content, settings, errors), with algorithm names/pseudocode/code samples staying English always, plus RTL layout support.

**Architecture:** A `LocaleProvider` (mirroring the existing `SettingsProvider` context+localStorage pattern) exposes `useLocale()` → `{ locale, setLocale, t }`. `t(key)` looks up a flat string key in `en.json`/`ar.json`. Components swap hardcoded text for `t('key')` calls. `<html lang dir>` toggles based on locale. RTL layout uses Tailwind logical properties (`ms-*`/`me-*`/`ps-*`/`pe-*`/`start-*`/`end-*`) instead of physical ones (`ml-*`/`mr-*`/`pl-*`/`pr-*`/`left-*`/`right-*`) in shared layout components.

**Tech Stack:** Next.js 15, React 19, TypeScript, existing `SettingsProvider`/`useLocalStorage` patterns.

**Spec:** `docs/superpowers/specs/2026-07-05-arabic-i18n-design.md`

## Global Constraints

- Algorithm/data-structure names, pseudocode, and the 12-language code viewer contents stay in English always — never put these behind `t()`.
- `npx tsc --noEmit` and `npm run build` must stay green after every task.
- Dictionary keys are typed (`Record<DictKey, string>`) so a missing translation is a compile error, not a silently blank UI string.
- Every new dictionary key added in one task must exist in BOTH `en.json` and `ar.json` before that task is committed.

- [ ] **Step 2: Create the `i18n` module**

Create `src/lib/i18n/index.ts`:

```typescript
"use client";

import * as React from "react";
import { useLocalStorage } from "@/lib/hooks";
import en from "./en.json";
import ar from "./ar.json";

export type Locale = "en" | "ar";
export type DictKey = keyof typeof en;

const DICTS: Record<Locale, Record<DictKey, string>> = { en, ar };

interface LocaleContextValue {
  locale: Locale;
  setLocale: (l: Locale) => void;
  t: (key: DictKey) => string;
}

const LocaleContext = React.createContext<LocaleContextValue>({
  locale: "en",
  setLocale: () => {},
  t: (key) => en[key],
});

export function LocaleProvider({ children }: { children: React.ReactNode }) {
  const [locale, setLocale] = useLocalStorage<Locale>("bdsv:locale", "en");

  React.useEffect(() => {
    document.documentElement.lang = locale;
    document.documentElement.dir = locale === "ar" ? "rtl" : "ltr";
  }, [locale]);

  const t = React.useCallback((key: DictKey) => DICTS[locale][key] ?? DICTS.en[key], [locale]);

  return (
    <LocaleContext.Provider value={{ locale, setLocale, t }}>{children}</LocaleContext.Provider>
  );
}

export function useLocale() {
  return React.useContext(LocaleContext);
}
```
